## Executive summary

1. **`pub` modules expose the entire engine internals as 1.0 API.** `lib.rs` declares ten `pub mod`s (`data_page`, `defrag`, `error`, `freemap`, `handle_table`, `overflow`, `page`, `page_cache`, `page_io`, `stats`, `superblock`, `transaction`). Every internal type and method these contain becomes part of Chisel's stability contract once 1.0 ships. The README presents an 18-method surface, but `chisel::transaction::TransactionManager`, `chisel::page::PAGE_SIZE`, `chisel::handle_table::HandleEntry`, and dozens more are equally public. (DESIGN)

2. **Core public types are not `#[non_exhaustive]`.** `Options` (6 fields), `ChiselError` (22 variants), `DrainInsertion` (2 variants), `SpillwayLocation` (2 variants), and `Stats` lack the attribute. Adding a field to `Options` or a variant to `ChiselError` is a breaking change today — only `ChiselCounters` carries `#[non_exhaustive]`. (DESIGN)

3. **CI runs no supply-chain check, no MSRV pin, and the root `Cargo.toml` is missing crates.io publication metadata.** No `cargo audit`/`cargo deny`, no `rust-version`, no `license`/`repository`/`readme`/`keywords` fields. The README claims a future crates.io release; today the manifest can't publish. `License: TBD` in the README is itself a finding. (DESIGN — same flag as prior review's F6, still open)

4. **`page_io.rs:136` invokes `libc::flock` inside `unsafe { … }` with no `// SAFETY:` comment.** The single `unsafe` block in the core engine — and the only one anywhere outside the bench crate's documented `slice::from_raw_parts` — silently violates the project's stated comment standard for the layer the entire single-writer contract rests on. (SMELL)

5. **Spillway module carries stale `#[allow(dead_code)]` on every exported item.** The attributes were added during phased landing ("Suppressed until spillway is wired into PageCache (Tasks 7-8)"); the spillway IS wired in (`page_cache.rs:824` and surrounding) and the attributes now suppress nothing real, hiding a future regression where one of these items legitimately becomes dead. (SMELL)

## Findings by category

### Correctness

- **SMELL — `src/transaction.rs:1375-1379`**: `delete_inner` ends with `unreachable!("handle_table::delete returns None for Deleted entries; None was already escalated to InvalidHandle by ok_or above")`. The "unreachable" depends on `HandleTable::delete`'s behavior — a real cross-module invariant. If a future refactor changes that contract, this becomes a library-reachable panic instead of `CorruptPage`. Direction: convert to `Err(ChiselError::CorruptPage { page_id: entry.page_id })` and document why the variant was chosen.

- **SMELL — `src/transaction.rs:1846`**: `DataPage::insert(buf, value).expect("value fits in empty page")`. Reachable if `insert` ever changes to return `None` for any reason besides "no room" (e.g., size overflow on a misuse). The invariant is currently sound but un-asserted at a type level. NIT: keep but add a `// INVARIANT:` comment naming the data-page contract you rely on.

- **NIT — `src/lib.rs:411`**: `file_size_bytes: page_count * page::PAGE_SIZE as u64`. Multiplication without `checked_mul`; overflows at `u64::MAX / 8192 ≈ 2.25 × 10^15` pages (18 EiB) — unreachable but unannotated. Direction: `saturating_mul` is one character of armor and removes the theoretical panic.

- **NIT — `src/page_cache.rs:865`**: `let entry = self.entries.remove(&victim_id).expect("LRU referenced page id not in entries");` — reachable if the LRU index and entries map ever desync. Currently kept in sync by `discard`/`truncate`/`flush`. Direction: prefer `match … { None => return Err(ChiselError::CorruptPage{page_id: victim_id}) }` since a desync is genuinely an invariant violation worth surfacing typed rather than as a panic.

- **NIT — `src/page_cache.rs:188, 211, 353, 384, 914`**: five `.unwrap()` sites on hashmap `get` / `Option<Spillway>` access immediately after the cache was populated or the spillway was just constructed. Each is invariant-backed but unannotated; in aggregate they're a "trust the local code" pattern that a maintenance read can't verify quickly. Direction: at minimum, annotate each with a one-line `// INVARIANT: …` comment naming what guarantees the `Some`.

### Ownership and borrowing

- **No finding.** The `RefCell<PageCache>` choice is rigorously justified in `src/transaction.rs:118-128` and `src/lib.rs:9-12` — single-writer, `!Sync` by construction, `&self`-taking reads serialize through the borrow checker via the borrow_mut at each call site. The pattern is consistent across every call site (`borrow_mut` for the duration of the operation, no held borrows across closures). I looked for held-`RefMut`-across-callback hazards and didn't find any.

- **NIT — `src/transaction.rs`** consistently calls `self.cache.borrow_mut()` and then `&mut cache` for downstream `&mut PageCache` parameters. This is a hand-rolled reborrow pattern that's correct but verbose. Reasonable trade-off for clarity over a wrapping helper.

### Error handling

- **DESIGN — `src/error.rs`**: `ChiselError` has no `#[non_exhaustive]` attribute (the enum was added pre-1.0 but is positioned as a public stability boundary by the README's "Operational vs Fatal" promise). Adding a variant is a breaking change for `match` ergonomics in caller code, even when `is_fatal()` shields callers from per-variant logic. Direction: add `#[non_exhaustive]` before 1.0; the 22 existing variants stay; only `match _` becomes required.

- **DESIGN — `src/error.rs:215`**: `impl std::error::Error for ChiselError {}` provides no `source()` override. The `IoError(io::Error)` variant wraps the inner error but `e.source()` returns `None`, breaking error-chain walkers (e.g., `anyhow::Error::root_cause`, structured logging). Direction: implement `fn source(&self) -> Option<&(dyn Error + 'static)>` to expose the inner `io::Error` for `IoError` and any other variants that carry a cause.

- **DESIGN — `python/src/errors.rs:209-215`**: `to_py_err` discards the inner `io::Error` from `IoError(_)` (it formats via `Display` then drops the variant). A Python caller cannot programmatically distinguish ENOSPC from EACCES from EIO — they all become `chisel.IoError("I/O error: <prose>")`. The comment at 211-213 documents the choice as "the string is the only cross-boundary contract"; that's defensible but worth re-litigating if any caller wants disk-full-vs-permission-denied handling.

- **SMELL — `bench/src/engine.rs:43`**: `pub type EngineResult<T> = Result<T, Box<dyn Error + Send + Sync>>;` erases the underlying engine error class. The trait is internal (`publish = false`), so this isn't a true public-API leak, but downstream test/diagnostic code can't `match` on engine-specific errors without `downcast`. Direction: a thin `EngineError` enum (`Chisel(ChiselError) | Redb(redb::Error) | Sqlite(rusqlite::Error)`) would preserve introspection while keeping the existing `?`-friendly ergonomics via `#[from]`.

- **NIT — `src/page_cache.rs:691, 718, 728`**: the three runtime setters return `Result<()>` but all three are infallible today. `set_drain_insertion` literally is `self.drain_insertion = policy; Ok(())`. The `Result` shape is hedging for future fallibility, but right now the type signature lies about the API. Direction: drop the `Result` on `set_drain_insertion` (truly infallible) and leave the other two `Result`-returning with a brief future-proofing comment.

### Async

- **No finding.** No `async fn` anywhere in the codebase. The README and ARCHITECTURE.md both commit to a synchronous, single-writer API. PyO3 calls release the GIL via `py.allow_threads` only at `open()`-time I/O (per-op calls stay GIL-held, with the rationale documented at `python/src/db.rs:466-484`).

### API design

- **DESIGN — `src/lib.rs:22-35`**: 12 `pub mod` declarations expose `data_page`, `defrag`, `error`, `freemap`, `handle_table`, `overflow`, `page`, `page_cache`, `page_io`, `stats`, `superblock`, `transaction`. Every type and method in those modules — `TransactionManager`, `HandleEntry`, `PageCache::set_next_page_id`, `Superblock::serialize`, `OverflowChain`, `DEFAULT_SUPERBLOCK_COUNT`, etc. — becomes part of the 1.0 stability promise. The actual public API documented in the README is 18 methods on `Chisel`. Direction: switch internal modules to `pub(crate)` and re-export only the genuinely public types (`Options`, `DrainInsertion`, `Chisel`, `ChiselError`, `Stats`, `ChiselCounters`, `DefragOptions`, `DefragStats`). This is the single highest-leverage change before 1.0.

- **DESIGN — `src/lib.rs:80-88` (`Options`)**: 6 public fields, `#[derive(Debug, Clone)]`, no `#[non_exhaustive]`. Adding `cache_warmup_pages: u64` (or any other future tuning knob) is breaking. Direction: `#[non_exhaustive]` plus a `Options::builder()` would be conventional Rust; minimally, just add the attribute.

- **DESIGN — `src/lib.rs:99-102` (`DrainInsertion`)** and `src/lib.rs:107-111` (`SpillwayLocation`): both `pub enum`, no `#[non_exhaustive]`. A third drain policy or a third spillway backing would break callers using `match drain_insertion { LruTail | Mru }`. Direction: `#[non_exhaustive]` on both.

- **DESIGN — `src/lib.rs:107-111` (`SpillwayLocation`)**: public, but its only legitimate construction sites are inside `Chisel::open` and `Chisel::open_in_memory_with_options`. It's part of the `PageCache::new` constructor signature, which would not need to be public if `page_cache` were `pub(crate)`. Currently the type leaks because `pub mod page_cache` does. Direction: make `SpillwayLocation` `pub(crate)` once `page_cache` is gated.

- **SMELL — `src/transaction.rs:1693-1699`**: `pub fn current_roots(&self) -> (u64, u64, u64)`. A public method that returns a positional 3-tuple `(handle_table_page, freemap_page, next_handle)` is a stringly-typed API in tuple clothing — the caller has to remember which slot is which. Used by tests and the Python binding (well, not really — the binding doesn't reach for it). Direction: introduce `CurrentRoots { handle_table_page, freemap_page, next_handle }` struct, or `pub(crate)` the method entirely.

- **SMELL — `src/lib.rs:264-267`**: `Chisel::close(self) -> Result<()>` is always `Ok(())`. The method consumes `self`, so the `Result` is currently theatre. The doc justifies it as future-proofing for fsync-on-close failures. Reasonable but worth a `#[must_use = "Chisel::close may surface errors in a future release"]` to make the future-proofing observable.

- **NIT — `src/transaction.rs:1700-1703`**: `pub fn is_active(&self) -> bool`. Doesn't really need a doc comment, but it's `pub` on a `pub` type — which is fine if `transaction::TransactionManager` is meant to be public; not fine if not. Decided by the same `pub(crate)`-modules question above.

### Type system usage

- **SMELL — `src/transaction.rs:417, 423`**: `if root_buf[1] == 0x02 { ... }` and `let child = u64::from_le_bytes(buf[child_offset..child_offset + 8].try_into().unwrap());` use a raw hex literal for the FLAG_INTERIOR byte rather than the `FLAG_INTERIOR` constant from `handle_table.rs`. The constant exists (per `ARCHITECTURE.md`'s description of the page layout); reaching for the hex literal in `open_existing` defeats the single-source-of-truth promise. Direction: import `handle_table::FLAG_INTERIOR` (or expose it if it's currently private) and compare against it.

- **NIT — `src/error.rs:38`**: `InvalidSuperblockCount { value: u32 }` is a struct variant for "user passed bad superblock_count". This is fine, but ergonomic-only: the validated range `MIN_SUPERBLOCKS..=MAX_SUPERBLOCKS` is the real type-system gap — a `SuperblockCount(u32)` newtype enforced at `Options` construction would make `InvalidSuperblockCount` unreachable on the open path. Parse-don't-validate territory; not a blocker.

### `unsafe`

- **SMELL — `src/page_io.rs:133-141`**: the entire `try_lock` function is:
  ```rust
  fn try_lock(file: &File) -> Result<()> {
      use std::os::unix::io::AsRawFd;
      let fd = file.as_raw_fd();
      let rc = unsafe { libc::flock(fd, libc::LOCK_EX | libc::LOCK_NB) };
      if rc != 0 {
          return Err(ChiselError::LockFailed);
      }
      Ok(())
  }
  ```
  No `// SAFETY:` comment. CLAUDE.md (gitignored, but the source-tree convention is the same) and the file's own header both call out `flock` as the load-bearing single-writer mechanism. The invariants this `unsafe` upholds — fd is valid for the call's duration via `&File`'s borrow, the syscall returns an `errno`-style int that we check, no resources are leaked because flock release is tied to fd close — are exactly what a `// SAFETY:` block should document. Direction: add the comment naming each invariant.

- **No further unsafe in core engine.** Only two `unsafe` blocks exist outside test code: this one and `bench/src/chisel_engine.rs:101` (which DOES carry a thorough SAFETY comment, matching the prior review's F5 recommendation).

### Concurrency

- **No finding.** The single-writer + `flock` + `RefCell` model is internally consistent and well-defended in comments. The `Cell<bool>` poison flag and `Cell<u64>` counters are explicitly justified as `!Sync`-compatible (`src/transaction.rs:206-209`, `src/page_cache.rs:107-114`). The PyO3 binding's reentrancy hazard is documented at `python/src/db.rs:17-29` with a concrete recipe for handling it if a callback API is ever introduced — that's an unusually clear forward-compat note.

### Performance

- **SMELL — `src/transaction.rs:1217`**: `Ok(data.to_vec())` (prior review F2, unchanged). At 8 KB values, every `read()` allocates and memcpys ~8 KB per call regardless of cache state. The hot path is documented in the prior review. Direction unchanged: a `read_borrow(&self, handle: u64) -> Result<Ref<'_, [u8]>>` sibling API would close this for Rust-side callers; PyO3 callers cannot benefit because `PyBytes` wants owned bytes.

- **SMELL — `src/page_io.rs:166-167`**: `read_page` calls `self.page_count()?` every call, which on the file backing does `file.seek(SeekFrom::End(0))` — one extra lseek syscall per read miss. Comment at 156-163 documents the cost and the rationale (no cache invalidation complexity). For workloads with high miss rates this is real; the comment underweights it ("absorbed by `PageCache` on cache hits") because the cache miss IS the cost site by definition. Direction: a cached `next_page_id`-style high-water-mark in `PageIo`, invalidated by `write_page` past EOF and by `set_page_count`, would eliminate the seek with two write paths to update.

- **SMELL — `src/page_cache.rs:340-358`**: `flush()` collects dirty IDs into `Vec<u64>` for every flush. Sized to `dirty_count`, so for a 10K-page transaction that's 80 KB transient allocation per commit, repeated on every commit. The collect-first idiom is a borrow-checker dodge; a `RefCell<Vec<u64>>` cached on `PageCache` and reused across flushes would eliminate the per-commit allocation. Marginal but real. Direction: reuse a scratch `Vec<u64>` on `self`.

- **NIT — `src/page_cache.rs:182, 184, 205, 207, 298`**: prior review F3 — two `Cell<u64>` ops per `get`/`get_mut`/`new_page`. Still present, still deliberate per the prior review's resolution (option (a) "accept the cost"). Not re-flagged.

- **NIT — `bench/src/chisel_engine.rs:106`**: `self.db.stats()?.file_size_bytes` calls `stats()`, which walks the entire handle table (O(live handles)). Used per measurement cell in the bench harness — for 100K-handle scenarios this is ~milliseconds per call. The bench infrastructure cares about this. Direction: a dedicated `Chisel::file_size_bytes() -> Result<u64>` that bypasses the handle walk and just reads `page_count * PAGE_SIZE` would avoid the work.

### Tests

- **DESIGN — `bench/` test isolation**: per ARCHITECTURE.md and CLAUDE.md, the bench subcrate is a sibling — not a workspace member — so `cargo test` from the repo root doesn't run `bench/`'s tests, and `ci.yml` doesn't either. The spillway-rollout retrospective in CLAUDE.md flags this as a pattern that bit a real PR. Direction: add a `bench` job to `ci.yml` that does `cd bench && cargo test`, gated to PR + main pushes. ~2 minutes added; closes a real coverage hole.

- **SMELL — repeated `std::mem::forget(file)` test pattern**: at `src/transaction.rs:2211`, `src/page_cache.rs:930, 1000`, and elsewhere. `NamedTempFile` cleans up via `Drop`; tests that need the file to outlive the `NamedTempFile` value (because they re-open the path) leak the temp file deliberately. This is fragile: the leaked path stays in `/tmp` after the test exits. Direction: use `tempfile::TempDir` and construct paths inside it; `TempDir`'s `Drop` cleans up the directory and everything in it, including a re-opened sibling. The spillway test at `src/spillway.rs:338-365` already does this correctly.

- **NIT — no `#[should_panic]` invariant tests for the `unreachable!` and `expect` sites**: the codebase has good regression tests for documented invariants (I1, I3, I7, I18, I27, I28, I29 all have dedicated tests). The `unreachable!` at `src/transaction.rs:1375` and the `expect` at `src/page_cache.rs:865` describe invariants that would benefit from a `#[should_panic(expected = "…")]` test exercising the invariant-violating path via a stub or mock. Lower priority.

- **NIT — no property tests (`proptest`/`quickcheck`) for byte-roundtrip code**: `Superblock::serialize` / `deserialize`, `DataPage` slot packing, freemap bitmap operations are all natural fits for property testing. The current targeted tests cover known cases well; property tests would cover the unknown ones. Optional pre-1.0.

### Cargo hygiene

### Idiomaticity

### Security

- **No critical finding.** The only `unsafe` in core engine is the documented `libc::flock` (modulo the missing SAFETY comment, flagged above). No FFI beyond that; no `as` casts that could truncate at trust boundaries that I noticed (the `usize as u8`-style conversions are all sourcing from XXH3 hash output where every bit is meaningful, or from page-format constants that are < 256 by spec).

- **NIT — `flock` is advisory, not mandatory**: documented in README and ARCHITECTURE. An external tool that doesn't respect advisory locks can scribble on the file. This is a Linux/macOS POSIX limitation, not a Chisel bug, but worth ensuring is called out in any future ops/recovery doc.

- **NIT — `Chisel::Drop`** doesn't fsync. If a user forgets to `commit()`, shadow paging guarantees the on-disk state is the last committed state, so this is correct-but-surprising for callers from other ecosystems. Documented in `Chisel`'s type-level doc comment, line 139-141 — adequate.
